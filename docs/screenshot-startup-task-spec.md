# 任务：缩短截图快捷键到选区出现的等待

## 目标
优化用户按下截图快捷键后，选区界面出现慢的问题。

## 用户已提供的上下文
- 用户反馈截图响应迟钝，已明确发生在快捷键按下到选区界面出现之间。
- 前序 Teams 拖拽和图片重名修复已安装；本轮保留这些未提交修改。

## 范围内
- `ScreenshotCoordinator.swift` 的启动等待及 `CaptureTools.swift` 的屏幕冻结路径。
- 核查系统截图接口、显示器坐标及像素尺寸、取消、权限失败与连续启动。
- 运行相关回归，构建、备份并更新本机安装，验证实际选区能够出现和取消。

## 范围外
- 改动截图标注工具、快捷键配置、用户历史和授权设置。
- 后台持续录屏或预先保存屏幕内容。

## 用户约束
- 以用户明确的截图启动阶段为优化重点。

## 系统假设（不是用户事实）
- 继续现有框选、调整和标注流程，采用只在触发截图时采集的方案。
- 用户要求修复当前使用的软件，沿用已授权的本机应用更新流程。

## 未确认项
- 用户使用物理快捷键的最终体感，以及与 PixPin 的同口径比较。
- 本机阶段耗时及当前双屏实际操作已补充到 `screenshot-startup-validation.md`。

## 验收标准
- 普通截图不再无条件增加 250 毫秒等待，也不再为选区底图执行 PNG 编码、落盘和重复解码。
- 快捷键仍能显示正确屏幕内容供框选，取消后可再次启动。
- 多屏坐标、Retina 尺寸、权限拒绝及显示器变化保持正确处理。
- 不改用户设置、截图倒计时、历史数据及前序修复。

## 验证要求
- 从本地 SDK 和 Apple 文档确认接口及系统版本要求。
- 使用合成图片/注入依赖验证坐标、数量、失败及取消处理，运行已有截图生命周期回归。
- 区分代码消除的固定等待、合成测试和真实桌面操作证据；没有基准时不声称百分比提速。
- 保持签名身份，检查已安装路径和启动状态。

## 交付物
- 实现、相关回归、简明验证记录及本机更新。

## Agent 行为
- 已检查当前仓库和已有未提交修改。
- 实现前先给出计划；继续处理已授权可逆工作。
