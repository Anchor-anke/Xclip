# Xclip.Core

无 Windows API 和第三方包依赖的 `net10.0` 历史存储库。`HistoryStore` 每次成功写入后更新 `Entries`；失败抛出异常，由界面显示。公开列表及文件路径数组均为副本。

## 数据与恢复

- `history.json`：严格的 `schemaVersion: 1` JSON；逐项验证字段、类型、ID、重复内容及附件。未知版本、损坏数据和无效路径直接报错并保留原文件，不以空历史覆盖。
- `attachments/<SHA256>.png`：独立附件，内容校验、PNG 结构及尺寸检查。附件名只允许小写 SHA256 + `.png`，拒绝路径穿越及数据文件/附件目录符号链接。PNG 像素解码由 Windows 图片适配层负责。
- 构造加载和显式读图检查附件字节；普通提交对已验证图片检查文件大小和修改时间，仅发生变化时重新读取并计算 SHA256，避免每次复制文字读取全部图片。
- 写入先落同目录临时文件并 flush，再通过文件系统重命名替换。附件先写入、元数据后提交；进程中途退出至多留下未引用附件，不会先写入指向尚未保存附件的元数据。文件系统/硬件断电持久性仍取决于操作系统。
- `history.lock` 对本库的并发写入实施文件锁；写入时核对已加载元数据 SHA256，拒绝以旧快照覆盖另一实例或外部修改。
- 文本按精确内容、图片按 PNG 字节 SHA256、文件列表按 Windows 路径大小写规则去重；重新复制保留原 ID、收藏和置顶，更新时间与来源。

## 删除和容量

- 默认保留最新 300 条普通记录；收藏或置顶免于普通记录裁剪。所有记录合计仍有 1000 条硬上限，达到后新写入报错，保护数据不会被偷偷删除。
- 单条删除（包括受保护记录）及清除普通记录可以撤销一步；清除不删除收藏或置顶。撤销快照仅驻留本次进程，成功采集或修改标志会使旧撤销失效。操作失败保留原历史和撤销能力。
- 图片附件在当前历史或撤销快照仍引用时保留。成功提交后尽力回收无引用的标准 PNG 附件；上次运行残留的无引用 PNG 也会在后续成功写入时回收。未知文件保留。
- 单条文本/文件路径总长上限 1,048,576 字符；文件列表最多 256 项、单路径最多 32,767 字符；来源应用最多 1024 字符；查询最多 4096 字符。
- 单 PNG 最多 32 MB、最长边 16,384 像素、6400 万像素；元数据最多 32 MB。新增图片前检查附件目录总计最多 512 MB / 4096 个文件（包括未识别文件及撤销所需附件）；达限拒绝写入，用户可删除图片并使撤销失效后释放空间。既有目录不会因为超限而被自动清空。

## 自动验证

```sh
dotnet run --project windows/Xclip.Core.Tests/Xclip.Core.Tests.csproj
```

无 NuGet 测试框架，使用真实隔离临时目录验证持久化、去重、搜索、标志、保护与裁剪、删除撤销、损坏元数据/附件保护、路径穿越、并发旧快照、安全输入和容量。可在 macOS、Linux、Windows 运行；不代表 Windows 剪贴板/粘贴/截图的实机验收。
